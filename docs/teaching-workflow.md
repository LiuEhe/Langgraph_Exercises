# 教学组织与目录约定

## 先写什么

先写本课讲义初稿，明确“要解决什么问题、使用哪些 API、运行后看到什么、怎样判断掌握”，再编写配套示例与练习。代码运行后回填实测结果，形成可以正式学习的一课。

这不是一次写完八周教材。八周路线保留为提纲，每次把当前一课准备完整；根据学习者反馈调整下一课。

`AGENTS.md` 保存协作规则，README 提供入口，完整教学内容放在 `docs/lessons/`。聊天用于答疑和反馈，重要结论回写到对应讲义或学习记录。

## 文件分别放哪里

以下为目标结构，标明“按需”的目录和文件尚未创建。它们在相应课程或项目阶段产生内容时再创建。

```text
langgraph/
├── AGENTS.md                      # 教学与工程协作规则
├── README.md                      # 学习入口、环境和运行方式
├── pyproject.toml                 # Python 版本与直接依赖
├── uv.lock                        # 锁定依赖版本
├── .python-version                # Python 3.12
├── .env                           # 用户本地配置，不提交
├── .env.example                   # 可提交的配置格式示例
├── docs/
│   ├── teaching-workflow.md       # 本文：备课与目录约定
│   ├── lesson-template.md         # 新课讲义模板
│   ├── lessons/
│   │   ├── README.md              # 课程索引与备课状态
│   │   └── 01_state_node_edge.md  # 按需：第一课讲义
│   └── learning-log.md            # 按需：实际学习进度
├── examples/                      # 按需：导师完整示例
│   └── 01_state_node_edge/demo.py
├── exercises/                     # 按需：学习者的练习
│   └── 01_state_node_edge/exercise.py
├── solutions/                     # 按需：讲评时的参考解答
│   └── 01_state_node_edge/solution.py
├── src/agent_learning/            # 按需：完整业务项目源码
└── tests/                         # 按需：关键行为测试
```

每课共用一个标识，如 `01_state_node_edge`。文档使用这个名称加 `.md`，代码使用同名目录，避免只看到 `demo.py` 却不知道对应哪篇讲义。

同一课需要多个示例时，可以增加 `demo_stream.py` 等明确命名的脚本，并在讲义中逐个给出用途和运行命令。

学习者在 `exercises/` 中写代码。导师先阅读已有作答再反馈；示例与解答分别存放，不能用标准答案覆盖练习。

后续引入 `src/agent_learning/` 时，应同时配置项目打包和 uv 安装，使模块可正常导入。当前没有业务包，不预先添加空框架或修改 `sys.path`。

## 一课如何准备与完成

1. **确定一课目标。** 根据最近学习记录选择一个主要问题，例如“节点只返回一个字段时，其他字段会怎样”。写清前置知识，明确是否需要真实模型。
2. **先写讲义初稿。** 从 [模板](lesson-template.md) 创建课程文档，写明具体导入、方法参数、返回类型、执行流程、文件路径、预期结果和练习验收。
3. **创建示例与练习。** 示例完整可运行，练习只提供任务所需骨架。参考解答在学习者需要或进入讲评时再创建。课程文档链接到实际文件。
4. **执行与验证。** 从项目根目录运行命令，检查输出和重要分支。模型课使用 `.env`，首次调用控制输出长度与重试次数；离线课不访问模型。
5. **完善讲义。** 根据运行结果修正说明，记录依赖版本、实测行为、常见报错及排查方式。缺少依赖、代码或验证时保持“待验证”。
6. **正式学习。** 按讲义解释示例，让学习者预测结果，再运行观察，随后在练习文件中独立修改。
7. **讲评与记录。** 根据作答指出具体问题，必要时提供解答。将已验证能力、待巩固点和下一步写入 `docs/learning-log.md`。

备课完成不需要额外等待一次例行批准；按用户已经授权的教学范围推进。引入新的付费服务、明显扩大任务或缺少关键配置时，再提出具体问题。

## 每篇讲义写到什么程度

| 内容 | 必须能回答的问题 |
| --- | --- |
| 场景和目标 | 本课解决什么问题？学完能独立做什么？ |
| 前置条件 | 需要哪些知识、文件、依赖、模型能力？ |
| API 说明 | 从哪里导入？关键参数是什么？接收与返回什么类型？ |
| 示例讲解 | 状态如何变化？哪一步在调用模型、工具或普通函数？ |
| 运行方法 | 从哪个目录、使用哪条实际命令运行？ |
| 预期与实测 | 应出现什么结果？导师实际验证了什么？哪些还没测？ |
| 效果和限制 | 功能是否达到目标？质量、延迟、token、费用有哪些证据？ |
| 练习和验收 | 学习者改哪个文件？输入是什么？用什么行为判断正确？ |
| 常见问题 | 常见报错怎么复现和定位？ |
| 后续衔接 | 下一课解决哪个尚未覆盖的问题？ |

例如教 `bind_tools`，讲义应展示模型返回的 `tool_calls`，说明绑定不会执行工具；再展示程序执行工具并返回 `ToolMessage` 的过程。效果验证检查工具名、参数与结果如何进入上下文，而不是只展示一句最终回答。

模型输出只展示必要片段。token、费用、延迟没有测量时写“未测”；准确率需要固定样例和评估口径，不能用一次演示代表整体效果。

## 现有 .env 如何用于课程

当前配置使用自定义 `LLM_*` 名称：

| 变量 | 程序如何使用 |
| --- | --- |
| `LLM_PROVIDER` | 当前 `openai_compatible` 映射到 `model_provider="openai"`，选择 `langchain-openai` 适配包 |
| `LLM_MODEL` | 显式传入模型初始化参数 `model` |
| `LLM_API_KEY` | 显式传入 `api_key`，不打印或写入讲义 |
| `LLM_BASE_URL` | 显式传入 `base_url`，使用用户配置的服务地址 |
| `LLM_TIMEOUT_SECONDS` | 解析为正数后传入 `timeout`；不是控制输出 token 数的参数 |

这些变量不会由 LangChain 自动映射。供应商标记说明协议类型，真实能力还需逐项验证。配置格式见根目录 [.env.example](../.env.example)，不要用模板覆盖用户已有文件。

在首个模型课程中补装适配包：

```powershell
uv add langchain-openai
```

随后运行模型课的实际脚本：

```powershell
# 示意命令，替换为课程中已创建的脚本
uv run --env-file .env python path/to/model_lesson.py
```

uv 加载 `.env` 后，代码通过 `os.environ` 读取配置；无需再增加 dotenv 库。仅运行 `uv run python ...` 不会自动读取根目录 `.env`。[uv 官方说明](https://docs.astral.sh/uv/concepts/projects/run/#environment-variables)

查看配置是否齐全不代表认证、网络或模型调用成功。当前已检查配置项存在、供应商标记和超时格式，未安装模型适配包、未发送真实请求。

## 状态如何记录

- **待编写**：只有提纲，还没有正式讲义。
- **草稿**：讲义已写，配套代码或验证尚未齐全。
- **待验证**：代码已写，但需要运行、补环境或核对行为。
- **可学习**：讲义、示例、练习与必要验证齐全；模型能力没有验证的部分明确标记。

以上是备课状态，维护在 [课程索引](lessons/README.md)。学习者的“未学习、练习中、需巩固、已验收”等状态另记在学习日志中。

导师运行成功只能证明对应示例行为已验证，不能将学习者状态自动改为“已验收”。
